# 迭代记录：Codex 交接助手 1.0.0 → 1.2.0

本记录对应工作目录中的 `Codex交接助手-1.2.0`。原始 `D:\Desktop\Codex交接助手-1.1.2\Codex交接助手` 保持不变；本目录是在其基础上完成至少 80 轮实质迭代后的交付副本。

每轮均围绕正确性、完整性、可读性、性能、边界情况或一致性中的至少一项展开。轮次 1–35 为 1.1.x 基线加固，轮次 36–84 为 1.2.0 的界面、校验、增量、构建与交付完善。最终隔离测试共 108 项通过（引擎 79、界面 25、构建/校验 4），EXE 自检与隐藏界面冒烟测试通过。

## 1. 清单结构、类型与数量校验
- 目标：拒绝损坏或恶意迁移包在触碰文件系统前进入流程。
- 改动：新增 `validate_manifest`，校验格式版本、快照编号、父编号、必填字段、根目录、文件条目、类型、大小和重复路径。
- 理由：中转目录可能经过网盘或人工复制，必须按不可信输入处理。
- 自检：`test_malformed_manifest_rejected`、`test_snapshot_with_malformed_manifest_is_refused` 通过。

## 2. 清单文件数量、总大小与路径深度上限
- 目标：避免超大清单耗尽内存或磁盘。
- 改动：增加 `MAX_MANIFEST_FILES`、`MAX_MANIFEST_BYTES`、路径深度/长度检查，并给出中文原因。
- 理由：清单是元数据，不应无限增长；损坏清单应快速失败。
- 自检：清单上限相关测试通过，后续又补充根目录数量上限测试。

## 3. Store 并发初始化
- 目标：两台电脑同时首次选择同一中转目录时不互相覆盖身份。
- 改动：`store.json` 使用临时文件、硬链接/独占创建和校验，`Store.initialize` 只读认领已有身份。
- 理由：中转目录可能被两端同时初始化。
- 自检：`test_store_identity_is_stable_under_concurrent_creation` 用 8 个线程通过。

## 4. Store 对象与元数据链接拒绝
- 目标：防止链接把写入引到中转目录之外。
- 改动：对象、`store.json`、`latest.json`、快照目录统一走 `no_link`/`safe_file` 检查。
- 理由：链接和 Windows 目录联接不能被当作普通文件处理。
- 自检：`test_store_rejects_directory_and_linked_objects`、`test_publish_refuses_linked_snapshot_directory` 通过。

## 5. Windows 保留名称校验
- 目标：恢复路径在 Windows 上可创建。
- 改动：拒绝 `CON`、`PRN`、`AUX`、`NUL`、`COM1-9`、`LPT1-9` 及其带扩展名形式。
- 理由：这些名称在 Windows 上可能映射到设备，导致复制或恢复失败。
- 自检：`test_windows_path_aliases_and_reserved_names_rejected` 通过。

## 6. 尾随空格、句点和控制字符
- 目标：拒绝 Windows 会静默截断或无法表示的路径片段。
- 改动：`windows_component_problem` 检查尾随空格/句点、控制字符、空片段和 255 字符上限。
- 理由：静默截断可能让两个文件写到同一路径。
- 自检：同一路径校验测试覆盖 `file.`、`folder /file`、`bad\x01name` 等输入。

## 7. 绝对路径长度上限
- 目标：避免超过 Windows 扩展路径上限。
- 改动：`safe_file` 在拼接后检查 `MAX_ABSOLUTE_PATH`，超限直接报“路径过长”。
- 理由：超长路径在复制中途失败会留下半完成状态。
- 自检：`test_absolute_path_length_limit` 通过。

## 8. JSON 读取错误中文化与 BOM 兼容
- 目标：让用户看懂损坏文件的原因。
- 改动：区分找不到文件、非 UTF-8、JSON 行列错误、文件过大和 I/O 错误；使用 `utf-8-sig` 接受 BOM。
- 理由：原始异常对普通用户不可操作。
- 自检：`test_json_errors_are_actionable_and_bom_is_accepted` 通过。

## 9. JSON 原子写入
- 目标：设置、状态和清单不会因中途失败留下半个文件。
- 改动：同目录临时文件写入、`fsync`、`os.replace`，失败时清理临时文件；POSIX 下同步父目录。
- 理由：同步目录和断电场景下，非原子写入会产生不可解析状态。
- 自检：`test_json_errors...` 与全套状态测试通过；后续补充不可序列化数据测试。

## 10. 空 Codex 数据导出、状态与恢复标记校验
- 目标：阻止无意义导出和损坏状态继续操作。
- 改动：`has_exportable_data` 要求至少有一份可导出内容；`validate_state`、`validate_recovery` 校验编号、项目和恢复记录。
- 理由：空导出或损坏标记会让用户误以为交接成功。
- 自检：`test_empty_or_corrupt_source_cannot_export`、`test_malformed_recovery_marker_is_explained` 通过。

## 11. 盘符根路径映射
- 目标：修复 `C:\` 到 `D:\` 等根路径映射。
- 改动：`_mapping_key`、`_mapped_target` 单独处理盘符根，避免把 `C:\` 当成普通目录前缀。
- 理由：用户目录可能位于不同盘符，根路径映射错误会产生 `D:\\file` 或相对路径。
- 自检：`test_path_mapping_drive_roots_and_trailing_slashes` 通过。

## 12. 尾斜杠与大小写不敏感映射
- 目标：同一目录的带/不带尾斜杠、不同大小写写法能正确归并。
- 改动：映射键统一 `normcase`，按最长前缀排序，保留目录边界。
- 理由：Windows 路径大小写不敏感，手工配置容易混用。
- 自检：扩展路径、尾斜杠和大写测试通过。

## 13. 项目目录祖先、子目录和大小写重复校验
- 目标：避免同一文件被两个项目根重复迁移。
- 改动：`validate_projects` 使用解析后的规范路径，检查身份重复、祖先/子目录重叠和与 Codex/工具目录重叠。
- 理由：重复项目会造成清单冲突和删除范围扩大。
- 自检：`test_project_boundaries_and_case_insensitive_duplicates` 通过。

## 14. 进程扫描缓存与结果解析
- 目标：减少重复扫描，并正确识别 Codex 进程。
- 改动：缓存进程 API 函数签名，改用 `csv.reader` 解析 `tasklist /FO CSV`，处理空行和 BOM。
- 理由：直接按逗号切分在带逗号的路径或本地化输出下不可靠。
- 自检：进程识别测试组通过。

## 15. `codex-tui.exe` 等进程名识别
- 目标：覆盖 CLI/TUI/执行器进程。
- 改动：候选集合加入 `codex-tui.exe` 等名称，并保留 ChatGPT 路径判别。
- 理由：只检查 GUI 主程序会漏掉后台 CLI。
- 自检：`test_codex_tui_name_blocks`、`test_all_codex_process_names_block` 通过。

## 16. SQLite 错误包装
- 目标：数据库损坏、锁定或版本不兼容时给出可操作提示。
- 改动：`sqlite_open`、`database_check`、`schema` 捕获 `sqlite3.Error` 并转换为 `HandoffError`。
- 理由：原始 SQLite 异常包含实现细节，用户无法判断该退出程序还是换版本。
- 自检：`test_corrupt_database_check_is_a_handoff_error` 通过。

## 17. 远程凭据清理与安全删除
- 目标：导出包不携带来源电脑的远程控制注册信息。
- 改动：`db_copy` 对两个数据库删除 `remote_control_enrollments`，启用 `secure_delete` 并 `VACUUM`，复制后复查计数。
- 理由：远程凭据不应随聊天记录跨机传播。
- 自检：两个凭据清理测试通过，导出对象字节中不含测试令牌。

## 18. `prepare` 二次校验
- 目标：接收前再次验证清单和目标边界。
- 改动：`prepare` 重新调用 `validate_manifest`、`destinations`、`safe_file`，逐文件核对大小和 SHA-256。
- 理由：从读取清单到复制之间，清单或中转对象可能被替换。
- 自检：损坏对象、路径越界和重复文件测试通过。

## 19. 磁盘空间预检查
- 目标：在修改目标前发现空间不足。
- 改动：`ensure_free_space` 在暂存和目标应用阶段检查可用空间，保留 64 MiB 余量。
- 理由：复制到一半才失败会留下需要恢复的状态。
- 自检：`test_prepare_refuses_when_staging_space_is_insufficient` 通过。

## 20. 接收时跳过未变化文件
- 目标：减少重复写入和磁盘/同步压力。
- 改动：`apply` 对目标文件做大小和 SHA-256 比较，相同则保留原文件。
- 理由：重复接收相同快照不应重写所有文件。
- 自检：`test_receive_does_not_rewrite_unchanged_files` 通过；后续修正为与暂存内容比较。

## 21. 先复制后删除与失败回滚
- 目标：替换过程中崩溃仍可恢复。
- 改动：先写临时文件并替换，再删除多余文件；失败时用接收前备份自动回滚，并保留恢复标记。
- 理由：先删除会让失败后的目标目录不可用。
- 自检：`test_failure_during_copy_restores_previous_snapshot`、`test_failure_after_apply_automatically_rolls_back` 通过。

## 22. 数据库路径回写显式事务
- 目标：数据库路径更新要么全部成功，要么全部回滚。
- 改动：`remap_database` 使用 `BEGIN IMMEDIATE`，只更新已知路径列，提交后再次 `quick_check`。
- 理由：部分更新会让聊天记录与工作目录不一致。
- 自检：往返路径、扩展路径和 JSON 载荷测试通过。

## 23. 批量数据库更新与按需重写 JSON
- 目标：减少数据库写放大，避免无变化 JSON 被重新格式化。
- 改动：收集变更行后 `executemany`；`payload`/`metadata` 只有映射结果变化时才写回。
- 理由：大量附件行逐条提交很慢，且重写会破坏原有格式。
- 自检：`test_json_payload_paths_are_remapped_without_reformatting_other_rows` 通过。

## 24. 数据库 schema、版本和编码校验
- 目标：阻止不同 Codex 版本之间盲目替换数据库。
- 改动：`database_signature` 比较 `sqlite_master`、`user_version`、`application_id`、`encoding`。
- 理由：结构不兼容会导致应用启动后无法读取聊天。
- 自检：不同 `user_version`、不同 schema 测试通过。

## 25. 全局桌面状态合并
- 目标：只迁移允许的聊天/项目字段，保留目标电脑其他设置。
- 改动：`GLOBAL_KEYS` 白名单、`merge_global_state` 合并、路径映射，写入暂存区后再应用。
- 理由：直接覆盖整个全局状态会破坏目标电脑的机器专属设置。
- 自检：往返测试验证 `machine-only` 保留，后续补充禁止键测试。

## 26. 快照目录安全路径
- 目标：防止快照编号或路径把写入引到目录外。
- 改动：`safe_file` 校验相对路径、解析后边界、父级链接和绝对长度。
- 理由：快照编号来自中转目录，不能直接拼接到文件系统。
- 自检：`test_path_traversal_and_auth_injection_rejected` 通过。

## 27. 父级链接检查
- 目标：即使目标文件尚不存在，也拒绝链接父目录。
- 改动：`no_link_path` 逐级检查现有父目录的符号链接/目录联接。
- 理由：只检查叶子文件会漏掉链接父目录。
- 自检：`test_linked_parent_is_refused_even_when_leaf_does_not_exist` 通过。

## 28. 绝对路径长度保护
- 目标：在写入前发现超长路径。
- 改动：`safe_file` 拼接后检查 `MAX_ABSOLUTE_PATH`；失败信息包含中文原因。
- 理由：Windows 扩展路径长度限制因系统配置而异，提前失败更安全。
- 自检：长度上限测试通过。

## 29. `hashlib.file_digest` 流式计算
- 目标：提高大文件哈希性能并降低内存占用。
- 改动：`digest` 改用 `hashlib.file_digest`，不再手工分块读取。
- 理由：热路径位于 C 层，速度更快且代码更短。
- 自检：`test_digest_matches_hashlib` 通过。

## 30. 同操作文件指纹缓存
- 目标：一次导出中同一文件不重复哈希。
- 改动：`fingerprint` 接收缓存，以路径、大小、mtime、ctime 为键；变更前后关键位置清空缓存。
- 理由：数据库大文件可能被多次读取。
- 自检：增量对象复用测试通过；后续补充无变化导出测试。

## 31. 文件遍历与清单顺序确定化
- 目标：同样内容产生稳定清单，便于比较和增量。
- 改动：目录/文件按 casefold 排序，清单最终按根和路径排序。
- 理由：`os.walk` 顺序不稳定会让无变化导出看起来不同。
- 自检：`test_manifest_paths_are_deterministic` 和新增排序测试通过。

## 32. 清单大小与复制后内容一致性
- 目标：防止复制期间源文件变化导致清单与实际对象不一致。
- 改动：`capture` 复制前后比较大小，`Store.put` 对临时对象计算哈希，失败则停止。
- 理由：同步目录中的文件可能在读取过程中被应用修改。
- 自检：导出变化检测和对象损坏测试通过。

## 33. UI 状态详情不截断
- 目标：长错误原因完整显示，方便定位。
- 改动：状态详情使用可换行标签，失败时自动展开详情并写入日志。
- 理由：截断错误会让用户无法判断是路径、空间还是版本问题。
- 自检：`test_long_error_is_not_truncated` 通过。

## 34. UI 损坏设置回退、记住方向和保存失败容错
- 目标：设置文件损坏或只读时仍能完成交接。
- 改动：读取失败回退默认值并提示；保存方向和项目；保存失败只记录日志，不阻塞操作。
- 理由：设置是便利功能，不应成为迁移阻塞点。
- 自检：`test_corrupt_settings...`、`test_settings_save_failure_does_not_block_export` 通过。

## 35. UI 添加项目即时校验
- 目标：在添加项目时就阻止重复、嵌套和与 Codex/中转目录重叠。
- 改动：`add_project` 解析路径，检查重复/祖先/子目录、Codex 目录和中转目录重叠。
- 理由：等到导出才失败会让用户重复操作。
- 自检：`test_add_project_validates_nested_and_duplicate_paths` 通过。

## 36. UI 中转路径规范化
- 目标：兼容用户从资源管理器复制来的带引号路径、环境变量和相对路径错误。
- 改动：`normalize_store_path` 去引号、展开环境变量/`~`、要求绝对路径、拒绝文件和链接、解析后保存。
- 理由：路径格式错误是最常见的首次使用失败原因。
- 自检：`test_normalize_store_path_rejects_invalid_and_expands_values` 通过。

## 37. UI 接收确认信息完整化
- 目标：让用户在替换前看清来源、时间、文件数、项目数和目标路径。
- 改动：确认框显示来源电脑、ISO 时间转本地时间、文件/项目数量、目标路径和会删除快照外文件的警告。
- 理由：接收会替换本机数据，必须提供足够上下文。
- 自检：`test_receive_confirmation_cancel_and_accept` 通过。

## 38. UI 确定进度与百分比
- 目标：让用户知道处理到哪一步。
- 改动：引擎 `report_progress` 回调逐文件上报，界面切换到 determinate 进度条并显示 `done/total` 和百分比。
- 理由：只显示“正在处理”无法判断是否卡住。
- 自检：`test_progress_event_updates_determinate_bar` 通过。

## 39. UI 键盘快捷键
- 目标：支持键盘操作且避免重复触发。
- 改动：Enter 开始、Ctrl+O 选目录、Alt+1/2 切换方向、F1 详情；焦点在按钮/文本/列表时把 Enter 交给控件自身处理。
- 理由：按钮已有 Return 绑定，顶层再处理会打开两个确认框。
- 自检：`test_keyboard_shortcuts_switch_direction`、`test_keyboard_start_ignores_focused_button_and_text` 通过。

## 40. UI 损坏交接状态回退
- 目标：状态文件损坏时不丢失设置中保存的项目列表。
- 改动：状态读取失败时改用 `settings.json` 的项目，并单独提示“状态不可读”，不再误称为损坏设置。
- 理由：状态和设置是不同文件，错误提示和回退来源应准确。
- 自检：`test_corrupt_state_uses_saved_projects` 通过。

## 41. UI 接收成功后的项目刷新容错
- 目标：接收已经成功时，项目列表刷新失败不能把结果改成失败。
- 改动：`work` 中单独捕获 `state()` 刷新异常，写日志后仍发送 `done`。
- 理由：状态读取是附属操作，不应回滚已完成的文件替换。
- 自检：`test_receive_success_survives_state_refresh_failure` 通过。

## 42. UI 恢复流程确认与成功状态
- 目标：恢复备份必须有明确确认，并显示成功/取消。
- 改动：恢复按钮走统一 `start("restore")`，取消不调用引擎，成功后显示“备份已恢复”。
- 理由：恢复会再次替换本机文件，必须防止误触。
- 自检：`test_restore_confirmation_and_success` 通过。

## 43. UI 忙碌/空闲关闭行为
- 目标：操作中禁止关闭，避免后台线程写入已销毁界面。
- 改动：`close` 在 `busy` 时提示等待；空闲时取消 `after` 轮询并销毁窗口。
- 理由：中途销毁窗口会丢失进度和错误提示。
- 自检：`test_close_busy_and_idle` 通过。

## 44. UI 日志复制与布局报告
- 目标：方便用户把错误日志发给维护者；完善冒烟报告。
- 改动：详情面板增加“复制日志”，复制到剪贴板并显示提示；`report` 增加版本和方向。
- 理由：手工选中复制长日志容易遗漏。
- 自检：`test_copy_log_and_layout_report` 通过。

## 45. UI 目标路径预览折叠
- 目标：项目很多时确认框不超过屏幕。
- 改动：`path_preview` 最多显示 8 个路径，其余显示“另有 N 个目标目录”。
- 理由：确认框过长会遮挡按钮或无法阅读。
