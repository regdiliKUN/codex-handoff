# Codex 交接助手 1.1.2

适用于两台 Windows x64 电脑轮流使用同一套本地 Codex 聊天记录。双击 `CodexHandoff.exe` 即可，无需安装 Python。

这是根据本机存储结构制作的辅助工具，并非 OpenAI 官方迁移功能。已完成隔离测试，尚未在第二台实体电脑上验证原聊天续聊。首次请按下文做一次往返验收，再用于日常交接。

## 打开图形界面后这样操作

1. 选择方向卡片：左边“从这台电脑带走”，右边“接到这台电脑”。
2. 点击“选择文件夹”，选中转位置。
3. 点击底部整条蓝色的“开始导出聊天”或“开始接收聊天”按钮。

开始按钮固定在窗口底部，滚动页面也能看见。项目选择和日志默认收起；操作进度、完成后的下一步、失败原因会直接显示在按钮上方。备份恢复入口在右下角。

1.1.2 修复跨电脑接收时 `\\?\C:\...` 和 `\\?\UNC\...` 扩展路径没有适配用户名的问题。旧版会复制正文文件，却让部分数据库路径仍指向来源电脑，导致部分聊天无法打开。压缩的 `.jsonl.zst` 记录继续保留原字节。接收仍是整套快照替换，不会自动合并目标电脑独有聊天；这些聊天留在接收前自动备份中。

1.1.1 修复进程误判：普通 ChatGPT 的开机后台进程不再阻止交接。Codex 的主程序也可能叫 `ChatGPT.exe`，工具现在读取程序路径区分两者；确认是 Codex 时仍会阻止交接，并自动展开详情，显示 PID 和程序路径。如果开机后没有手动打开 Codex 仍被提示，请核对详情中的路径，检查 Codex 是否自启或驻留托盘后台。无法读取路径或无法识别来源的同名程序会明确提示，避免在 Codex 写入数据时覆盖文件。

## 第一次准备

1. 两台电脑安装相同版本的 Codex，分别登录同一个账号。各自配置模型、插件、skills 和工具环境。
2. 两台电脑各保留一份本工具。可以直接复制整个“Codex交接助手”文件夹。
3. 在你现有的网盘同步目录、NAS 或移动硬盘里建立一个空文件夹，例如 `D:\同步\Codex交接数据`。工具本身不提供联网传输。
4. 两台电脑的工具都选择这个中转文件夹各自对应的路径。对应的文件夹必须同步同一批文件，路径字符串无需相同。
5. 项目目录尽量保持一致，例如两台都使用 `I:\codex worktree`。盘符不同的项目，先在第二台安排相同路径；本版没有自定义盘符映射功能。

## 从 A 切到 B

**在 A 上：**

1. 等 Codex 任务结束，保存项目文件，完全退出 Codex（包括托盘后台）和所有 Codex CLI。普通 ChatGPT 可以保留运行。项目编辑器也应停止写文件。
2. 双击 `CodexHandoff.exe`，选择中转目录。
3. 如需携带项目，点击“添加项目”选择具体项目文件夹。留空则只迁移选定的聊天数据及 Codex 图片、可视化文件，项目由你自行同步。
4. 选择左侧“从这台电脑带走”，点击底部蓝色“开始导出聊天”。工具发现 Codex 仍在运行时会拒绝操作，不会强行结束进程。
5. 显示导出完成后，**等待网盘或 NAS 确认所有文件同步完毕**。移动硬盘则等待写入结束并安全弹出。
6. 离开后不要在 A 继续聊天或修改本次携带的项目，直到下次接收 B 的更新。

**在 B 上：**

1. 先确认中转目录已完整同步，完全退出 B 上的 Codex（包括托盘后台）和 CLI。
2. 打开工具，选择对应的中转目录，选择右侧“接到这台电脑”，点击底部蓝色“开始接收聊天”。
3. 核对来源电脑、时间和目标路径。确认后，工具会先备份 B，再用快照替换交接范围内的文件。**B 自己原有的聊天会进入本机备份，不会与 A 自动合并。**
4. 显示接收完成后，手动打开 Codex，检查聊天列表、项目路径和附件，在原聊天继续工作。

从 B 返回 A，执行完全相同的步骤：B 导出 → 等待传输完成 → A 接收。

## 首次验收：先做一趟 A → B → A

1. A 导出后，B 接收。检查最近两条旧聊天是否能打开，历史消息和项目是否正确。
2. 在 B 的一条旧聊天发送一句“这是一条 B 电脑迁移验证消息”，确认有回复。检查工作目录与工具环境。
3. B 退出 Codex并导出，A 接收，确认 A 能看到这条新消息并继续回复。
4. 有项目随包携带时，在 B 新建一个无关紧要的验证文件，确认 A 接收后也能看到。
5. 若聊天无法打开、项目路径异常或出现版本问题，停止继续交接，关闭 Codex，使用“恢复备份”。

## 覆盖范围与恢复

接收会恢复完整的交接快照，并删除交接范围内快照中不存在的旧文件；所选项目也遵循这个规则。请选具体项目，不要选择磁盘根目录或用户主目录。工具会拦截系统目录、目录重叠、路径越界和链接。

每次实际接收前，工具自动备份本机聊天及即将覆盖的项目文件。备份保存在 `%LOCALAPPDATA%\CodexHandoff\backups`，不依赖中转目录。关闭 Codex 后，点击“恢复备份”恢复最近一次接收前的状态。主动恢复前也会保存当前状态，因此再次恢复可以撤销该次主动恢复。

如果操作被关机或断电中断，工具会保留恢复标记，要求先执行“恢复备份”。恢复后交接关联可能被清除，需要重新确认接收。恢复按钮不会把已恢复的旧数据自动发布到中转目录。

聊天恢复范围：

- `sessions`、`archived_sessions`、`session_index.jsonl`。
- 本机验证过的 `state_5.sqlite` 和 `thread_history_1.sqlite`。
- `.codex-global-state.json` 中选定的项目、聊天路径和列表字段。目标电脑的其他桌面设置保留。
- `generated_images`、`visualizations`。
- 你明确添加的项目文件夹。普通独立 Git 仓库可以携带，包括 `.git`；排除 `node_modules`、`.venv`、`__pycache__` 目录，目标电脑需要重建这些依赖。

不自动迁移：`auth.json`、`config.toml`、插件安装、skills、claude-mem、自动任务/队列、日志、缓存、其他应用本地数据。来源电脑的远程控制注册信息会从导出数据库中清除，远程连接需要在目标电脑重新配置。所选项目里的文件不做凭据筛选，请自行确认项目选择范围。

两台用户名不同：工具适配活动数据库与项目元数据里的 Codex 数据目录、用户目录前缀。**聊天原文和 JSONL 字节不改动**，以保留历史记录及数据库读取偏移。因此历史消息中的旧路径仍可能出现；首次续聊应明确告诉 Codex 当前项目路径。其他盘符变化需你保持项目路径一致。

外部附件只在其所在目录被你添加或另行同步时才会到达另一台。Git worktree、子模块指针、Codex 托管 worktree 及其 Git 注册关系暂不支持自动迁移；遇到 `.git` 指针文件时项目导出会停止。普通项目中的安装路径、Python 虚拟环境、CAD 工具、MCP 服务仍需分别配置。

## 冲突或接收失败

| 提示 | 操作 |
|---|---|
| 检测到 Codex 仍在运行 | 查看自动展开的详情中的 PID 和程序路径；Codex 也可能叫 ChatGPT.exe。结束任务后从托盘或菜单完全退出 Codex 与 CLI，再重试。 |
| 无法确认进程是否属于 Codex | 根据详情中的程序路径核对程序；路径无法读取时先退出对应程序再重试。 |
| 迁移包未同步完整或校验失败 | 等待下载全部完成；网盘中转文件夹设为始终保留在本机。不要只复制 `latest.json`。 |
| 本机在上次交接后有改动 | 本机有未导出的聊天、列表或项目变化；不要用其他同步软件强行覆盖。 |
| 另一台电脑有更新，无法直接导出 | 本机交接基线落后，应接收；若本机也有新内容则属于分叉。 |
| 两台数据库结构不一致 / 数据库版本未验证 | 统一 Codex 版本后再试。本版仅支持上述数据库文件名，不猜测新版结构。 |
| 上次操作被中断 | 先点击“恢复备份”。 |

**双方都有新内容时，不会自动合并。** 先分别备份两台电脑的完整 Codex 数据和相关项目，保留中转目录原件，再决定以哪一份继续、如何保留另一份记录。此时工具没有“强制覆盖”按钮，也不会自动新建分支同步库。

只要启动应用产生了新的受跟踪记录，也可能触发本机有变化的提示。侧边栏重命名、归档、项目文件修改都算本机变化。

## 增量与存储空间

第一次导出需要存放完整数据；这台电脑此前仅 `sessions` 就约 2.5 GiB。后续相同内容的文件复用已有对象，只有内容变化的文件及新的数据库快照需要传输。**这是文件级增量，不是单个大文件内的字节差量**；一个很大的聊天文件变化后仍需传输整个文件。

工具会计算哈希、暂存接收内容和保存本机备份，因此电脑和中转目录都应留出空间。中转目录保留历史对象，不会自动清理；不要手动删除 `objects` 里的文件。备份和中转数据都含聊天原文，没有加密，请放在你自己的受控目录中。

这不是双机同时编辑方案。工具会检查本机基线与已同步的最新标记，但无法识别网盘尚未送达的另一台更新。只有等同步结束、按 A/B 顺序交接，才能避免这种分叉。

## 文件与维护

- `CodexHandoff.exe`：Windows x64 便携程序。
- `handoff.py`、`handoff_ui.py`：交接引擎和图形界面源代码，Python 3.12+ 标准库即可运行。
- `tests/test_handoff.py`、`tests/test_handoff_ui.py`：引擎及界面隔离测试，不读写真实聊天。
- `验证记录.md`：已完成的检查及尚未验证的边界。
- `SHA256SUMS.txt`：交付文件校验值。

本机设置和备份在 `%LOCALAPPDATA%\CodexHandoff`。Codex 目录优先读取 `CODEX_HOME`，未设置时使用当前用户的 `.codex`；窗口中可以核对实际目录。

官方依据：[本地聊天及归档目录](https://learn.chatgpt.com/docs/reference/troubleshooting)、[CODEX_HOME 与本地状态](https://learn.chatgpt.com/docs/config-file/config-advanced)。数据库处理与交接协议是本工具的实现，并非官方跨机恢复承诺。
